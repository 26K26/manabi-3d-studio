# まなび3D Studio：学校向け・完全無料版の開発基準

更新：2026-10-29。開発中の仕様であり、全機能の動作保証ではありません。

## 譲れない条件

- 教員・生徒に利用料金、APIキー、外部サービスのアカウント登録を求めない。
- CAD → STL受け渡し → スライス → 印刷データ保存を、**アプリ内・端末内処理**で完結させる。外部スライスサイト、遠隔計算、有料APIへ処理を委ねない。
- 作品ファイルを自動的に外部へアップロードしない。
- 一般的な学校のWindows PC（8GB RAM）とChromebookを基準に、iPad/iPhoneにも配慮する。
- 初期設定の機種は Bambu Lab A1 mini、造形範囲 **180 × 180 × 180 mm**（20cmではない）。他校の機種はユーザーが範囲を変更可能。
- プリンター固有のG-code・.gcode.3mf互換性は、実機テストを終えるまで保証・案内しない。
- 生徒が使う主画面は「作る」「スライス」「保存」を軸にする。高度な設定は必要に応じて展開する。

## 機能の分離

1. **CAD:** 作図・編集・保存。スライサーに依存させない。
2. **学校のプリンター設定:** 無依存の `print-config.mjs`。A1 mini 180mm、他校の造形範囲、積層高さ、事前チェック。初期設定は固定、端末内で選択結果を保存。
3. **STL受け渡し:** IndexedDB等の同一オリジン内に一時保存し、外部へ送信しない。
4. **スライサーエンジン:** Kiri:Motoを当面の実験実装とし、将来交換できる独立した内部モジュールにする。外部スライスサービスは使用しない。
5. **機種別の印刷データ出力:** 内部で形式と開始・終了コードを検証し、対応確認済み機種のみ印刷可能と表示する。

## リリースの合格条件

- CAD/編集内容を失わず、エラー時に戻って再試行できる。
- 8GB Windows PCと管理対象Chromebook、iPhone/iPadで、実際の端末における基本操作とファイル保存を確認。
- 小・中・大の代表モデルについて、スライス完了だけでなく**結果のG-code / 3MF出力**を検証。大モデルは端末別の上限も明示。
- 最終公開物が全て静的ファイルで、CAD・スライスの実行時に第三者CDNや外部処理サービスを必要としない（**現状未達**：CADのThree.jsとCSGはCDNから読み込んでいる）。
- 学校のインターネット制限を想定した、自己ホスト/ローカル配布可能なパッケージを作る（**現状未達**）。
- Bambu Lab A1 mini等で、サンプル印刷の安全性と出力互換性を実際に検証する（**現状未達**）。

## 現在の達成と次の順番

1. **対応済み（実験）:** プリンター設定を独立モジュール化し、A1 mini 180mm固定・他機種カスタム・ブラウザ内保存・CAD→スライス前の造形範囲チェックを実装。
2. **次:** CADのThree.js / CSG等の外部CDN依存を除去し、全ライブラリを同梱して学校内ネットワークで動くようにする。
3. **次:** スライスエンジンの起動/状態/エラー/出力を内部APIとして分離し、CADを壊さずに差し替え可能にする。
4. **次:** Kiriの精度維持と省メモリを大きいモデルと8GB端末で評価。スライス完了後の印刷データ生成を必ずテストする。
5. **最後:** プリンターごとの実機印刷検証と、教員が設定を必要としない導線を完成させる。

**公開サイトやActionsのビルド成功は、全学校の端末での安定動作・実機印刷の成功を意味しない。**
